Design notes — 76 · Meetup admin screens

Scope: the five organizer screens of the events / RSVP feature — events dashboard (incl. drafts, cancelled, past), the create/edit event form, the AI recap editor (notes → generate → edit → publish), per-event attendees with check-in and an auto-promoting waitlist, and member role management with guard states. The member-facing screens live in 75-meetup-attendee.html.

Why this beats meetup.com / Luma: a real organizer console — draft vs published vs cancelled at a glance, capacity + waitlist in the same row, one-tap check-in on the door, CSV export, and an AI recap that turns rough notes into a publishable summary. Role management has the important guards built in (no self-demote, can't remove the last admin).

Design: matches mock-up 74 — Classic Blue accent, Poppins headings + Inter body, JetBrains Mono for labels/URLs/code, 5px radius, and the same light/dark behaviour, all through the shared --c-* contract variables. A left sidebar frames the admin console; each screen is shown in a browser window for legibility. Only the top toolbar toggle is interactive.

Offline: one self-contained file, zero network. Fonts embedded as base64 woff2 (same subset as 74); icons are an inline SVG sprite; links stubbed to #. The gemini-2.5-flash label reflects the recap model from the original spec.
